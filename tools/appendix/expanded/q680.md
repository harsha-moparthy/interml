**Visual inspection needs a reliable camera pipeline before a sophisticated model.** If lighting, focus, framing, or exposure changes unpredictably, an anomaly detector may learn those changes instead of defects. Define the inspection setup and defect categories with domain experts, then collect representative normal and defective examples.

**Why scarce defects suggest anomaly baselines.** A factory may have abundant normal images but few examples of each failure. A model of normal visual features can flag unusual patches for review without requiring a full classifier for every defect type. However, unusual does not always mean defective: a harmless new packaging variation can also be anomalous. [3]

**Split by production context.** Adjacent frames from the same object or batch are nearly duplicates. Randomly distributing them across training and test sets can inflate accuracy. Hold out production batches, times, or machines according to the intended deployment challenge.

At the edge, validate a compact model on the actual device and image pipeline. Quantization or resizing can erase small defects, so compare defect recall after optimization rather than assuming a faster model preserves the relevant signal. Missing or blurred frames should trigger a defined inspection fallback, not silently count as normal.

Measure missed defects by type and size, false rejects per unit, throughput, and manual-review load. Use real held-out failures to evaluate synthetic augmentation. Track acquisition quality alongside embedding/score drift so an alert increase can be diagnosed as a camera change, a new normal variant, or a true production problem.

**Technical details and references.**

Define defects with plant engineers and collect representative normal production across machines, batches, lighting, and camera positions. Split by production batch/time so almost-identical neighboring frames do not leak across evaluation. With scarce defect labels, start with a strong normal-feature/anomaly baseline and compare it with supervised or few-shot alternatives on real held-out defects.

At the edge, standardize acquisition, exposure, focus checks, and preprocessing. Optimize a compact model for the actual device, validate quantization, and reserve a deterministic reject/manual-inspection path when image quality is inadequate. Do not silently classify blurred or missing frames as normal. Version cameras, preprocessing, and models together.

Set thresholds from missed-defect and false-reject costs, not a balanced benchmark. Report defect recall by type/size, false rejects per unit, and inspection throughput. Monitor image-quality statistics and embedding/score drift to separate lighting changes from real process changes. Feed reviewed errors into an auditable labeling loop; synthetic defects can augment training but cannot replace evaluation on actual manufacturing failures.

**Mathematical and practical explanation.** A normal-data anomaly score can use distance to a reference feature distribution, but the threshold must be validated on real defects and legitimate production variation. Report missed defects and false rejects per inspected unit with uncertainty. Lighting or camera changes can shift scores without changing defect prevalence, so acquisition monitoring is part of the model system. [3](https://arxiv.org/abs/2304.07193)
