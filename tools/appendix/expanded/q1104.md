**BERT turns each input token into a context-dependent vector; the output head determines the task.** In the original model, the vector entering the first layer is a sum of token, position, and segment embeddings. These components encode what the token is, where it occurs, and which of the two segments it belongs to. [1][2]

For a paired input, use `[CLS] A [SEP] B [SEP]`. Segment IDs distinguish A from B; they are not sentence meanings or attention permissions. Position embeddings distinguish order. The attention mask suppresses padding positions. BERT's ordinary encoder attention can use both earlier and later non-padding tokens. [3]

Now choose the head. For whole-input classification, map the `[CLS]` representation to class scores and train a cross-entropy loss. For token classification, map each token representation to label scores. For extractive question answering, produce start and end scores over passage positions, then select a valid span. These heads have different output shapes even though the underlying encoder architecture can be shared.

Suppose a batch contains $B$ examples of length $T$ and hidden width $d$. Encoder output has shape $B\times T\times d$. A sentiment head yields $B\times C$ scores; a tagging head yields $B\times T\times C$. A span head commonly yields two $B\times T$ score arrays. Shape reasoning often catches a mistaken training objective before any GPU run.

**Watch subwords.** A word such as an unfamiliar surname may split into several tokens. For named-entity tagging, explicitly choose first-subword supervision or a consistent all-subword scheme, and map predictions back to words. Ignore padding in the loss. For QA, restrict candidate spans to the passage and enforce end after start. Finally, raw `[CLS]` vectors are not automatically good cosine-similarity sentence embeddings: sentence-embedding training such as Sentence-BERT addresses a different objective. [4][5]
