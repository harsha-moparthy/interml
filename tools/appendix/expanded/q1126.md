**Temperature zero usually means greedy selection, but greedy selection alone does not guarantee identical outputs across all executions.** Reproducibility also depends on numerical computation, software, model versions, inputs, and the surrounding application. [1]

Greedy decoding chooses $\arg\max_i z_i$ from the logits. If the top two logits are extremely close, a tiny numerical difference can change the winner. Once one token changes, all subsequent predictions condition on a different prefix, so a tiny initial difference can produce a large final text difference.

Floating-point addition is not associative: $(a+b)+c$ can differ from $a+(b+c)$ after rounding. Parallel reductions, different kernels, precision modes, and hardware can therefore produce slightly different results. Some operations are explicitly nondeterministic. A random seed controls relevant pseudorandom draws; it does not automatically control these other sources. [1][2]

For a reproducible experiment, record the exact checkpoint, tokenizer, prompt serialization, software and hardware versions, precision, decoding configuration, seeds, and relevant deterministic settings. Freeze retrieval results or record their versions too: a changing search result can alter an answer even if model execution is perfectly repeatable.

**Distinguish reproducibility levels.** Bit-for-bit equality is stronger than equal task accuracy within uncertainty. A research comparison may need repeated runs and error bars; a regression test for deterministic parsing may need exact output. Choose the standard that matches the decision, and state it explicitly.

PyTorch documents that reproducibility is not guaranteed across releases, platforms, and CPU/GPU execution. Deterministic settings can also reduce speed or reject unsupported operations. Therefore avoid promising “temperature zero plus seed equals deterministic everywhere.” Test the actual deployment configuration, preserve the execution metadata, and use semantic or structured-output checks when exact wording is not the product requirement.
