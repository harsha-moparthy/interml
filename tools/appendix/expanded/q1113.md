**Weight tying reuses the vocabulary embedding table as the output classifier's weights.** It reduces parameters and couples how a token is represented as input with how it is scored as output. It does not tie every parameter in the transformer. [1]

Let the embedding table be $E\in\mathbb R^{V\times d}$. Input token $i$ retrieves row $E_i$. An untied output head needs another matrix $W\in\mathbb R^{V\times d}$ and produces logits $Wh+b$. With tying, logits become $Eh+b$, so a token receives a high score when its embedding aligns with the hidden state.

For a vocabulary of 50,000 entries and width 1,024, eliminating the separate output matrix saves 51.2 million parameters. At two bytes per parameter, that is about 102.4 MB of raw weight storage in decimal units. Optimizer and gradient storage can increase training savings; the exact total depends on precision and optimizer implementation.

The shared table receives gradients from both roles. Input occurrences update the representation used to read a token; output predictions update rows according to the classification loss. Sharing changes the model's inductive assumptions, rather than merely compressing an otherwise identical trained network. In architectures with differing input and hidden widths, a projection or a different sharing scheme is needed. [1][2]

**What does it not save?** The vocabulary logits still have to be computed for an ordinary full-softmax prediction. Reusing weights does not eliminate the $V$-way output calculation. Likewise, sharing a matrix is not knowledge distillation or reduced-precision quantization, although these techniques may coexist. Check that checkpoint loading preserves parameter identity, not just equal initial values: two copied tensors that later train independently are no longer tied. Evaluate quality and memory separately because the parameter reduction is predictable, while the task-quality effect is empirical.
