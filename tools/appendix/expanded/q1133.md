**A contextual bandit chooses an action to obtain a reward for the current context; an MDP models actions that also change future states and rewards.** The key distinction is whether consequences beyond the immediate decision must be modeled. [1]

Choosing one headline for a visitor and measuring a click can be framed as a contextual bandit if future effects are intentionally ignored or negligible. Planning a robot's route needs an MDP because turning left changes where the robot is and which actions become possible next.

A bandit policy seeks a high expected immediate reward $E[r\mid x,a]$. An MDP policy seeks expected discounted return

$$J(\pi)=E_\pi\left[\sum_{t=0}^{\infty}\gamma^t r_t\right],$$

where transition probabilities determine the next state after an action. The state should summarize information needed to predict those transitions and rewards; a partial observation may require memory or a belief state.

**Delayed feedback alone does not necessarily make a problem an MDP.** A click recorded an hour later can still be bandit feedback if the action does not create relevant sequential consequences in the formulation. Conversely, an immediate click objective may hide long-term effects: repeatedly showing sensational content could change user trust and future engagement.

Prefer the simplest formulation that captures the decision's important consequences. Bandits can be easier to evaluate and learn from because they avoid modeling long trajectories. If sequential effects matter, reducing the task to immediate reward can systematically choose harmful long-term actions.

Before proposing an algorithm, specify context or state, action set, reward, horizon, available feedback, and exploration constraints. Then ask whether logged data covers the actions the proposed policy will take. Both bandits and offline MDP learning can fail when a new policy chooses actions absent from the logs; an elaborate value model does not create missing counterfactual evidence. [2][3]
